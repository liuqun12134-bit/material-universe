# Phase 1｜换品 Skill

## 目标

实现：

```text
原视频
+
新商品图
+
用户换品提示词
↓
换品视频
```

## 第一版只需要

- 可以读取原视频
- 可以读取商品图
- API Key 自动读取
- 默认使用 Google Gemini Omni Flash 视频模型
- 用户必须填写换品提示词
- Skill 内置最小保真约束，并与用户提示词合并
- 可以正常输出生成结果
- 出错时能看懂错误原因

## 已确认的输入辅助能力

- 产品原图先经过独立的图片分析与预处理 Skill。
- 默认视觉模型为 DeepSeek，默认生图模型为 Seedream。
- 合格图直接返回；不合格时只生成一次并复检。
- 两类模型均使用注册表和适配器，允许独立调用时选择模型。
- 不自动付费重试；模型异常由用户手动切换。

## 暂时不要

- 多模型切换
- Agent
- 云素材库
- 用户系统
- 完整 App
- 自动质量评分
- 复杂失败重试
- 复杂 Provider 框架

这里的“自动质量评分”指视频成片评分；产品参考图的合格检查属于已确认的换品输入要求。

## 完成标准

不是“跑通一次”。

而是：

```text
拿真实工作素材反复使用
↓
效果基本稳定
↓
知道常见失败原因
↓
已经能真正帮我工作
```

完成后再进入 Phase 2。

# Phase 2｜声音克隆 Skill

## 前提

换品 Skill 已经进入可稳定使用状态。

## 目标

实现：

```text
参考声音
+
目标文字
↓
新音频
```

## 第一版只需要

- 读取参考音频
- 读取目标文字
- 自动读取 API Key
- 默认使用指定声音模型
- 返回生成音频
- 有基本错误提示

## 根据真实使用再决定

是否需要：

- 自动降噪
- 音频切片
- 参考声音质量判断
- 多语言
- 情绪控制
- 多模型

## 完成标准

真实工作中可以稳定生成可用音频。

然后进入 Phase 3。

# Phase 4｜三个 Skill 完成后的复盘

这个阶段先不写代码。

先回答几个问题：

### 1. 三个 Skill 哪个使用频率最高？

### 2. 哪个 Skill 用户价值最高？

### 3. 哪些 Skill 经常一起使用？

例如：

```text
声音克隆
+
换口型
```

是否经常连续出现？

### 4. 是否已经出现固定 Workflow？

例如：

```text
输入视频
↓
生成新声音
↓
换口型
↓
输出
```

### 5. 是否真的需要产品壳？

如果套壳，前台到底应该展示：

```text
视频换品
声音克隆
口播重制
```

还是别的？

### 6. 是否需要素材库？

只有真实发现：

> 每次都要重复找素材、传素材，非常麻烦

再做素材库。

### 7. 是否需要 Agent？

只有真实出现：

> 用户不知道该选哪个功能，希望一句话让系统自己判断

再做 Agent。
