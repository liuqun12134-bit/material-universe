# 素材万象｜AGENTS.md

> 给 Codex 看的长期规则。
>
> 这里不是“项目全部设计”，只放少量长期有效的底线。

## 1. 当前项目目标

素材万象当前阶段不是做完整软件。

当前只做 3 个可独立使用的 Skill：

1. 换品 Skill
2. 声音克隆 Skill
3. 换口型 Skill

换品阶段允许增加一个职责单一的输入辅助 Skill：

```text
产品图片分析与预处理 Skill
```

它只负责把用户产品原图检查或转换为无中文多视角棚拍参考图，属于换品 Skill 的输入质量保障，不视为第四个产品功能。

三个 Skill 都经过真实内部使用、效果稳定之后，再考虑套产品壳。

---

## 2. Codex 必须遵守的规则

### 规则 1：优先简单

不要为了“以后可能需要”提前做复杂架构。

如果一个问题现在能用简单方式解决，就优先用简单方式解决。

---

### 规则 2：API Key 不能写死

API Key 可以提前配置，并自动读取。

开发阶段可以使用 `.env`。

但是不能把真正的 Key 直接写进代码，也不能提交到 Git。

---

### 规则 3：Skill 要能独立使用

每个 Skill 都应该能单独调用。

例如：

```text
换品 Skill
输入：原视频 + 商品图
输出：换品后的视频
```

不要让 Skill 必须依赖未来的 App、用户系统、数据库才能运行。

---

### 规则 4：允许默认模型

Skill 可以有默认模型。

例如换品 Skill 当前可以默认使用 Google 的指定模型。

用户不需要每次都选择模型。

但是不要把代码写成“永远只能使用这个模型”。

以后如果更换模型，应该尽量不用重写整个 Skill。

---

### 规则 5：Prompt 责任要写清楚

每个 Skill 必须明确：用户负责输入什么，Skill 固定维护什么。

换品 Skill 第一版由用户输入必填的换品提示词，Skill 只维护最小保真约束，例如：

- 商品图是新商品的唯一外观参考
- 只替换目标商品
- 其他人物、动作、镜头、背景、文字和音频尽量不变

不要把完整换品意图藏在 Skill 内，也不要忽略用户输入的提示词。

以后其他 Skill 是否内置完整核心 Prompt，根据真实效果单独决定。

---

### 规则 6：不要擅自扩大项目

当前没有明确要求时，不要主动开发：

- 完整 App
- 登录系统
- 支付
- 用户管理
- 多租户
- 云素材库
- Agent 平台
- 可视化 Workflow
- 插件市场
- 复杂模型路由

用户已经明确要求的产品图片预处理模型适配器除外；仍不得扩展成通用模型市场或自动付费重试系统。

---

### 规则 7：旧架构不是法律

如果实际开发发现 `ARCHITECTURE.md` 的某个设计太复杂、没必要或不适合当前需求：

不要为了符合旧文档强行实现。

应该：

1. 先选择更简单合理的方案
2. 说明为什么改
3. 更新 `ARCHITECTURE.md`
4. 必要时更新 `DECISIONS.md`

---

### 规则 8：重大改动不能悄悄发生

如果修改了以下内容：

- Skill 输入
- Skill 输出
- 默认模型
- API Key 读取方式
- 素材读取方式
- 核心 Prompt 结构
- Skill 之间的依赖关系

必须说明改了什么、为什么改。

---

## 3. 当前开发顺序

严格按下面顺序推进：

```text
换品 Skill
↓
真实使用并优化
↓
声音克隆 Skill
↓
真实使用并优化
↓
换口型 Skill
↓
真实使用并优化
↓
再考虑 Workflow / App / Agent
```

不要跳阶段。

---

## 4. 每次开发前

Codex 开始新任务前应先阅读：

- `AGENTS.md`
- `ARCHITECTURE.md`
- `ROADMAP.md`

如果任务涉及以前的重要技术决定，再查看：

- `DECISIONS.md`

---

## 5. 一句话原则

> 先把一个 Skill 真正做成能用的工具，再做下一个。  
> 不为了未来的“大产品”牺牲现在的开发速度。
