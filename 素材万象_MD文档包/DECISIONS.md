# 2026-08-18｜先做 Skill，不先做完整软件

## 决定

第一阶段先做三个 Skill：

1. 换品
2. 声音克隆
3. 换口型

三个 Skill 都内部真实使用后，再考虑套产品壳。

## 原因

目前最重要的是验证能力是否真的好用。

如果一开始就开发：

- 前端
- 登录
- 用户系统
- 支付
- 云素材库
- Agent

会增加大量和核心效果无关的工作。

## 当前状态

有效。

有效。

# 2026-08-18｜Skill 可以有默认模型

## 决定

Skill 可以默认使用某个模型。

用户平时不需要每次选择模型。

例如：

```text
换品 Skill
→ 默认 Google 指定模型
```

## 原因

如果每次都要求选择模型，会降低使用体验。

“不把模型写死”的真正意思是：

> 未来可以比较容易换模型。

而不是：

> 用户每次都要告诉 Skill 用哪个模型。

## 当前状态

有效。

---

# 2026-08-18｜API Key 只配置一次

## 决定

开发阶段 API Key 统一通过 `.env` 等配置方式读取。

用户不需要每次调用 Skill 都重新输入 Key。

## 原因

API Key 属于运行配置，不属于每次任务输入。

同时避免把真正的 Key 写死在代码中。

## 当前状态

有效。

---

# 2026-08-18｜核心 Prompt 由 Skill 自己维护

## 决定

普通用户不需要自己写完整 Prompt。

Skill 内部保存并持续优化核心 Prompt。

用户只保留“补充要求”入口。

## 原因

提示词本身就是 Skill 效果的一部分。

如果用户每次都要自己研究 Prompt，就失去了 Skill 的意义。

## 当前状态

已被后续决定部分替换：换品 Skill 第一版改为用户提示词必填，Skill 只维护最小保真约束。

# 2026-08-18｜换品第一版的提示词由用户输入

## 决定

换品 Skill 第一版的每次任务输入为：

```text
原视频
+
新商品图
+
用户换品提示词（必填）
```

Skill 不替用户决定完整换品意图，只固定附加：

- 商品图是新商品的唯一外观参考
- 只替换目标商品
- 其他人物、动作、镜头、背景、文字和音频尽量不变

## 原因

第一版需要让使用者直接控制换品目标和效果，同时保留少量稳定约束，减少模型误改视频其他部分。

## 当前状态

有效。

# 2026-08-18｜换品默认使用 Gemini Omni Flash 直编视频

## 决定

换品 Skill 第一版默认使用：

```text
gemini-omni-flash-preview
```

通过 Google Interactions API：

```text
上传原视频
+
绑定新商品参考图
+
用户提示词
↓
task=edit
↓
输出换品视频
```

不使用 Gemini Flash 图像模型逐帧处理。

## 原因

Gemini Omni Flash 是原生视频生成和编辑模型，可以同时接收文字、图片和最长 10 秒的视频，能直接完成视频编辑。逐帧图像编辑会增加调用次数，也更容易出现闪烁和时序不一致。

当前模型是预览版，输出限制为 3–10 秒、720p、24 FPS，以及 16:9 或 9:16；这些限制在真实使用中继续验证。

## 当前状态

有效。

# 2026-08-18｜不提前做多模型复杂架构

## 决定

第一版 Skill 先使用最简单的模型调用方式。

只有真实需求出现时，才增加：

- 多模型
- 模型路由
- 自动 fallback
- 前置理解模型
- 结果检查模型

## 原因

当前不知道这些复杂能力是否真的需要。

提前开发会降低迭代速度。

## 当前状态

有效。

# 2026-08-18｜确定流程优先 Workflow，Agent 后考虑

## 决定

三个 Skill 稳定以后，如果出现固定组合，再考虑 Workflow。

Agent 不作为第一阶段目标。

## 原因

例如：

```text
声音克隆
↓
换口型
```

如果流程固定，Workflow 更简单、更稳定。

只有需要系统自己判断下一步时，Agent 才真正有价值。

## 当前状态

有效。

# 2026-09-02｜换品前增加产品图片分析与预处理 Skill

## 决定

在换品流程前增加一个独立的产品图片分析与预处理 Skill：

```text
产品原图
↓
DeepSeek 视觉检查
├─ 合格：返回原图
└─ 不合格：Seedream 生成一次无中文多视角棚拍图
             ↓
           DeepSeek 复检后决定是否返回
```

视觉模型和生图模型分别使用注册表与适配器。独立调用 Skill 时用户可选择模型；素材万象接入时使用默认模型。不自动切换或连续付费重试。

## 原因

普通用户不会预先准备无中文多视角棚拍图，而带中文或不干净的参考图会增加视频模型乱码和产品外观不稳定风险。生图模型本身也可能不稳定，因此模型协议必须可替换，但第一版仍保持一次生成、一次复检的简单链路。

## 当前状态

有效。首版默认视觉模型为 `deepseek-v4-flash-vision-exp`，首个生图适配器为 `seedream-5.0-pro`。

# 新决定怎么记录

以后追加时使用：

```text
# YYYY-MM-DD｜决定名称

## 决定

...

## 原因

...

## 当前状态

有效 / 已废弃 / 已替换
```

如果旧决定被推翻，不要删除。

把旧决定标成：

```text

```
