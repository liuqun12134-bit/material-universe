# 写导演稿

## 1. 建立本次条件

先确定 `talk` 或 `use`。识别素材角色，不按附件顺序猜测。常规输入是首帧、人物参考、产品参考、完整原音频；可选产品说明、逐字稿、指定动作、平台约束和旧成功稿。缺可选参考不机械阻塞。用户明确产品信息优先，图像与声音只支持可观察的判断。

内部记录：品类、产品名（可未知）、形态、包装、可辨认结构、件数、初始开合、画面左右手各拿什么、可用操作手、可见承托面、演示部位、质地依据、目标效果。自拍镜像未知时先用画面左右定位，正式稿保持一套明确的手位定义。对标中看不到的桌面、盖子去向和内容物颜色不自动继承。

核实首帧与产品是否同款同规格；同款开合参考不等于与首帧冲突。首帧仍为旧品或数量目标不一致时，说明具体冲突并给修首帧建议，完成不依赖冲突的分析。未经图像编辑授权不修图，未解决的矛盾不能进入最终生成稿。

## 2. 音频与动作预算

真实读取总时长、台词、语种、语气、节奏和停顿；区分实测时长、可靠转写、用户稿、建议时间。按真实话题而非每五秒机械切段。缺转写时可以使用用户稿，但不能虚构句子时间戳。原声短时减少重复操作与部位，不通过变速、瞬移、假吸收塞入全流程。

## 3. 检索演示和经验

先读两个内置 index.json，并按 [自优化模块](self-optimization.md) 检索当前导演模式的外置 strategy/experience；去重后仅展开候选：

1. 模式须兼容；品类与形态匹配，产品名相同加分但不能掩盖包装或首帧冲突。
2. 比较包装、部位、初始状态、双手条件、承托和质地/效果依据。
3. 选可在原声内完成的少数演示单元；从途中阶段开始时继承首帧状态，不重复前序操作。
4. 阅读候选图片验证文字难以描述的接触和效果，不将对标人物身份、布景、包装或固定时间移入新稿。只有文字遗留资料时注明无法复查原视频。
5. 查询同问题、同模式及相近产品/包装/模型条件的经验。用户已确认有效经验在适用条件内优先；未确认经验仅作为待验证建议。用户明确需求与真实素材优先于所有经验。

没有合适记录就明确“库中暂无匹配案例”，基于材料和通用方法编排并标记未验证部分。不能把新设计冒充入库视频观察。无需为凑匹配而擅自新增演示记录。

## 4. 编排而非拼接

每个单元写清：起始状态 → 动作路径与实际接触 → 内容物/物体变化 → 结束状态 → 可辨认停留。相邻单元首尾相容。处理盖子占手、包装放置、操作手释放、部位一致性；没有可靠承托面不能凭空放桌上。

`talk` 重点在真实讲话和展示；`use` 必须争取适用产品的一次完整使用及效果停留。核心使用无法完成时指出具体条件不足，不能悄悄删成纯举品。原声完整、物理连续性与核心目的共同决定取舍。

## 5. 检查与交付

按 output-format.md 的七部分写一份完整正式稿。交付前检查：事实和推测分开；原声全程覆盖；双手与配件路径成立；结果从接触逐渐产生；输入素材编号一致；无旧图片前缀/空格、路径或默认输出比例；无互相抵消的允许/禁止事项；无对标身份/品牌污染；经验适用范围未扩大。

提示词检查通过不等于成片通过，不承诺一次生成精确口型、包装小字或时长。只说明实际完成的检查。
